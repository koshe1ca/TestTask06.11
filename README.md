# Semantic TextNavigator

Это небольшое веб-приложение для работы с договорами поставки. Оно читает текстовые документы, находит поставщика, сумму договора и срок поставки, а затем показывает, откуда взята эта информация.

Главная идея — не просто получить ответ, а иметь возможность сразу проверить его по исходному документу. Программа также учитывает подписанные дополнительные соглашения и отдельно показывает письма и неподписанные проекты, которые сами по себе не меняют условия договора.

Проект сделан в рамках тестового задания. В репозитории уже лежат все шесть TXT-файлов, которые были приложены к заданию.

## 1. Как скачать проект

1. Откройте этот репозиторий на GitHub.
2. Нажмите зелёную кнопку **Code**, затем **Download ZIP**.
3. Распакуйте скачанный архив в любую удобную папку, например на рабочий стол.
4. Откройте распакованную папку `TestTask06.11-main`. В ней должны быть файлы `server.py` и `start_windows.bat`, а также папки `documents`, `textnavigator` и `web`.

Ничего отдельно собирать или настраивать в GitHub не нужно.

## 2. Что нужно для запуска

На компьютере должен быть установлен **Python версии 3.10 или новее**. Если его нет, скачайте с [официального сайта Python](https://www.python.org/downloads/).

На Windows при установке Python желательно отметить пункт **Add Python to PATH**, если он появится. Это поможет компьютеру находить Python при запуске программы.

Устанавливать отдельные библиотеки, создавать аккаунты или получать API-ключи не нужно. Также понадобится обычный браузер: Chrome, Edge, Firefox или Safari.

## 3. Запуск на Windows

**Самый простой способ:**

1. Откройте папку проекта.
2. Дважды нажмите на файл `start_windows.bat`.
3. Должно открыться чёрное окно с запущенным сервером и вкладка браузера.
4. Если страница открылась раньше сервера и вы видите ошибку подключения, обновите её через несколько секунд.

Если браузер не открылся сам, перейдите по адресу:

**http://127.0.0.1:8501**

**Если запуск через .bat не сработал:**

1. Откройте папку проекта в Проводнике.
2. Нажмите на адресную строку папки, напишите `cmd` и нажмите Enter.
3. В открывшемся окне выполните:

```powershell
py -3 server.py
```

Если компьютер не понимает команду `py`, попробуйте:

```powershell
python server.py
```

После запуска откройте в браузере **http://127.0.0.1:8501**.

## 4. Запуск на macOS или Linux

Откройте Терминал и перейдите в папку проекта. На macOS можно написать `cd ` (с пробелом), перетащить папку проекта из Finder в окно Терминала и нажать Enter.

Затем выполните:

```bash
python3 server.py
```

Откройте браузер и перейдите по адресу **http://127.0.0.1:8501**.

**Важно:** окно с запущенным сервером нужно оставлять открытым, пока вы пользуетесь программой. Чтобы завершить работу, вернитесь в это окно и нажмите `Ctrl+C`. На Windows при запуске через `.bat` можно просто закрыть окно сервера.

## 5. Как пользоваться приложением

При первом открытии проще всего нажать кнопку **«Открыть учебный комплект»**.

Программа сама загрузит шесть документов из папки `documents`. Это три договора, подписанное дополнительное соглашение, письмо поставщика и неподписанный проект соглашения.

После загрузки появится таблица с договорами. В ней можно увидеть номер договора, поставщика, действующую сумму и срок поставки.

**Чтобы посмотреть конкретный договор**, нажмите на его строку в таблице. Ниже появятся подробности. Рядом с найденными значениями есть подтверждающие цитаты.

**Чтобы проверить ответ по тексту**, нажмите **«К источнику»**. Программа откроет соответствующий документ и выделит абзац, из которого взята информация.

В приложении также есть:

- **«4 вопроса»** — готовые ответы на четыре вопроса тестового задания с цитатами из документов.
- **«Диагностика»** — информация о том, какие документы распознаны, какие изменения учтены и где требуется ручная проверка.
- **Поиск по таблице** — позволяет быстро найти договор.
- **Выгрузка CSV** — сохраняет сводную таблицу, которую можно открыть в Excel.
- **Дата проверки** — позволяет посмотреть, какие условия действовали на выбранную дату.

Можно загрузить и свои TXT-файлы вместо учебного комплекта. Таблица будет построена по ним, но вкладка **«4 вопроса»** рассчитана именно на договоры из тестового задания.

## 6. Какой результат должен получиться

Для проверки установите дату **10.03.2026** и откройте учебный комплект.

| Договор | Действующая сумма | Срок поставки |
|---|---:|---|
| STN-101 | 1 380 000 ₽ | 30.04.2026 |
| STN-102 | 840 000 ₽ | 20.03.2026 |
| STN-103 | Нет данных | 30.04.2026 |

Почему именно так:

- **STN-101.** В первоначальном договоре указаны другие сумма и срок, но стороны подписали дополнительное соглашение № 1. Поэтому программа использует условия из этого соглашения. Более поздний проект № 2 не подписан и не учитывается.
- **STN-102.** Поставщик попросил перенести срок на 27.03.2026, но покупатель не согласовал изменение. Действующим остаётся срок 20.03.2026.
- **STN-103.** Цена должна быть в спецификации, которой нет среди предоставленных файлов. Указанный в договоре бюджетный лимит 600 000 ₽ не является ценой договора, поэтому программа показывает «Нет данных».

Из этих трёх договоров поставка **раньше 1 апреля 2026 года** предусмотрена только по STN-102.

## 7. Как проверить, что программа действительно читает файлы

Можно провести небольшой эксперимент:

1. Откройте файл `documents/03_contract.txt` в обычном текстовом редакторе.
2. Найдите сумму `840 000` и замените её, например, на `975 000`.
3. Сохраните файл.
4. Вернитесь в браузер. Нажмите кнопку выбора TXT-файлов и загрузите обновлённый набор из папки `documents`.

В таблице и подтверждающей цитате должна появиться новая сумма STN-102. Это показывает, что программа обрабатывает текст, а не просто выводит заранее сохранённые ответы.

После эксперимента верните исходную сумму `840 000`. Обратите внимание: кнопка **«Открыть учебный комплект»** читает файлы из папки проекта заново, поэтому изменение файла отразится и там.

## 8. Если программа не запускается

**Компьютер пишет, что Python не найден.** Установите Python с официального сайта, затем закройте и заново откройте командную строку.

**Страница не открывается.** Убедитесь, что окно с сервером всё ещё работает. Попробуйте открыть адрес вручную или обновить страницу.

**Порт 8501 уже занят.** В папке проекта запустите сервер на другом порту:

Windows:
```powershell
py -3 server.py 8502
```

macOS/Linux:
```bash
python3 server.py 8502
```

После этого откройте **http://127.0.0.1:8502**.

**Файл не распознался или значение отсутствует.** Посмотрите вкладку «Диагностика». Программа не должна придумывать сумму или дату, если в документе не хватает информации либо формулировка непонятна.

## 9. Что находится в папке проекта

- `documents/` — шесть исходных TXT-документов задания.
- `server.py` — запускает приложение на компьютере.
- `textnavigator/` — код, который анализирует договоры и формирует ответы.
- `web/` — внешний вид приложения и работа интерфейса в браузере.
- `tests/` — автоматические проверки правильности работы.
- `start_windows.bat` — быстрый запуск на Windows.
- `DEMO_SCRIPT.md` — сценарий показа программы на собеседовании.

Всё работает локально: для анализа документов не нужен доступ к интернету и они не отправляются в сторонний сервис. При этом настоящую подлинность подписей программа не проверяет — она определяет статус документов по тексту.

## 10. Как проверить код

Это необязательно для обычного использования, но полезно, если хотите убедиться, что основные сценарии работают правильно.

Откройте терминал в папке проекта и выполните:

На Windows:
```powershell
py -3 -m unittest discover -s tests -v
```

На macOS/Linux:
```bash
python3 -m unittest discover -s tests -v
```

Сейчас в проекте **29 автоматических тестов**. Они проверяют в том числе работу с подписанными и неподписанными документами, разные даты, отсутствующие суммы и ответы по исходному комплекту. Те же тесты запускаются автоматически на GitHub при обновлении кода.

## 11. Что важно знать об ограничениях

Это **учебный прототип**, а не готовая система для юридически значимого документооборота.

Сейчас он работает только с TXT-файлами (до 30 файлов за одну загрузку, размер каждого — до 2 МБ). PDF, Word-документы и сканы не поддерживаются. Сложные формулировки, несколько этапов поставки или нестандартные изменения могут потребовать ручной проверки.

Если развивать проект дальше, в первую очередь стоит добавить работу с PDF и DOCX, проверку действительности подписей, хранение истории документов и разграничение доступа пользователей.

## 12. Продуктовая записка (кратко, для проверки тестового задания)

**Для кого сделано.** Для специалиста по закупкам, который должен быстро сверить условия нескольких договоров и понять, какое изменение действительно вступило в силу. Программа помогает найти основание, но не заменяет проверку юристом.

**Пять вопросов заказчику перед развитием продукта:**

1. Откуда поступают договоры: из папки, электронной почты или системы документооборота?
2. Как подтверждается подлинность подписей и даты вступления изменений в силу?
3. Бывают ли несколько поставок, частичные отгрузки и разные сроки в одном договоре?
4. Какие документы обязательны для определения цены: спецификации, приложения, счета, протоколы?
5. Кто должен видеть и изменять документы, а кто — только просматривать результаты?

**Принятые допущения.** В тестовом комплекте шесть TXT, дата проверки — 10.03.2026. Договор определяется по тексту, а не имени файла. Менять сумму или срок может только допсоглашение, для которого в тексте подтверждены обе подписи и дата вступления в силу не позже даты проверки. Из применимых изменений выбирается более позднее по дате вступления в силу. Письма и проекты показываются как предложения. Если данных недостаточно или есть конфликт, выводится «нет данных» либо предупреждение. Реальную подлинность подписи программа не проверяет.

**Две метрики качества:**

- **Точность условий:** доля правильно найденных сумм и сроков, включая корректный вывод «нет данных», на заранее проверенном наборе документов. Каждое поле сравнивается с ручной разметкой.
- **Время проверки:** медианное время от выбора файлов до открытия цитаты с нужным условием. Сравнивается с ручной проверкой тех же договоров.

**Как устроено приложение:**

```text
Браузер (таблица, вопросы, цитаты)
       ↓
Локальный сервер на Python (server.py)
       ↓
Анализ текста и статуса документов (textnavigator/engine.py)
       ↓
Ответы по найденным условиям (textnavigator/qa.py)
       ↓
Браузер: результат + файл + точный абзац
```

**Три технических решения и компромисса:**

1. **Правила вместо вызовов языковой модели при работе программы.** Это бесплатно, предсказуемо и не требует передачи документов в облако. Недостаток — неизвестные формулировки иногда не распознаются.
2. **Сохраняем ссылку на исходный абзац для каждого найденного условия.** Пользователь может проверить ответ. Недостаток — при сложной структуре документа абзац может содержать больше одной строки.
3. **Один небольшой локальный сервер без базы данных.** Легко запустить без настройки. Недостаток — нет общей истории, совместной работы и управления правами пользователей.

**Если будет 100 000 документов и разграничение доступа.** Понадобятся база данных и хранилище оригиналов, очередь для обработки файлов, поиск и индексы, повторная обработка при изменении правил. Для пользователей — вход в систему, права на каждый документ и его цитаты, журнал действий. Нельзя разрешать выгружать данные, к которым у пользователя нет доступа.

**Три следующих улучшения в порядке приоритета:**

1. Проверять электронные подписи и даты изменений через систему документооборота.
2. Поддержать PDF/DOCX и более разнообразные формулировки, сохранив обязательные цитаты.
3. Добавить хранение версий, права доступа, поиск по большому архиву и журнал действий.

## 13. Краткий отчёт о разработке с помощью ИИ

**Инструмент:** ChatGPT (GPT-6). Он использовался для проектирования логики, написания Python-кода, интерфейса, тестов и документации. Приложение **не обращается к ИИ во время использования**.

**Три характерных запроса к ИИ** (переданы по смыслу, не дословная переписка):

1. «Сделай локальный прототип для шести TXT: три договора, подписанное допсоглашение, письмо и проект. Нужны таблица, сроки и суммы на заданную дату, четыре ответа и точные цитаты с переходом к источнику».
2. «Не считай письма и неподписанные проекты действующими изменениями. Если нет точной суммы или сроки противоречат друг другу, показывай “нет данных” и причину, а не придумывай результат».
3. «Проверь работу на исходных файлах, добавь тесты для дат, подписей и изменений текста; исправь ошибки, не зашивая ответы в программу».

**Ошибка и исправление.** Первоначально программа ошибалась на документах, где сумма записана как «1 200 000 (прописью) рублей», могла принять дату оплаты за дату поставки и бюджетный лимит за цену договора. После проверки на оригинальных TXT эти случаи исправлены, добавлены отдельные автоматические тесты; результат повторно проверен по первоисточникам.

**Фактические затраты и границы оценки.** Платные API и сторонние сервисы приложением не используются. По истории GitHub между первым коммитом 05.11.2026 в 14:02 UTC и обновлением основной инструкции в 16:20 UTC прошло около **2 часов 18 минут календарного времени**. Отдельный учёт человеко-часов не вёлся, поэтому это **не точная оценка трудозатрат** и не подтверждение времени подготовки до первого коммита.

**Что готово:** анализ TXT, применение подписанного соглашения, учёт предложений, цитаты, четыре ответа, интерфейс, оригинальные документы и автоматические тесты. **Что осталось за рамками тестового задания:** импорт PDF/DOCX, проверка настоящей электронной подписи, постоянное хранилище, права доступа и промышленный запуск. Эти функции намеренно не добавлялись в небольшой прототип.
